# Exam Task Generation Specification v1.0

> **Purpose**: Спецификация для генерации экзаменационных заданий LLM.  
> **Target**: Gemini / GPT / Claude  
> **Output**: Файл `exam_tasks.json`

---

## Отличия от обычных заданий (TASK_GENERATION_SPEC.md)

| Аспект | Обычные задания | Экзаменационные |
|--------|----------------|-----------------|
| ID | `py_01_var` | `exam_py_01_var` (префикс `exam_`) |
| Story | Развёрнутый RPG-нарратив | 1 предложение, лаконичная формулировка |
| Description | Может быть длинной | Чёткая, конкретная, проверяет знание |
| Campaign | Есть (act/chapter/order) | **Нет** |
| time_limit_minutes | Нет | **Обязательно** |
| Педагогика | Обучение + практика | **Проверка знаний** |
| Спойлеры | Допустимы подсказки | **Запрещены** между заданиями одного tier |

## Распределение по Tier

На каждый домен (python, javascript, frontend, scratch) — **10 заданий**:

| Tier | Кол-во | Концепты | Время | XP |
|------|--------|----------|-------|----|
| D | 3 | 1 концепт | 8 мин | 20-30 |
| C | 3 | 2 концепта | 12 мин | 40-60 |
| B | 2 | 2-3 концепта | 18 мин | 80-120 |
| A | 2 | 3+ концептов | 25 мин | 150-200 |

---

## Педагогические требования

1. **Проверка навыка, не обучение** — задание должно проверять, что ученик ЗНАЕТ концепт
2. **Без спойлеров** — решение задания tier D не должно подсказывать tier С
3. **Честная сложность** — не невозможно, но и не тривиально
4. **Один фокус** — D: 1 концепт, C: 2, B: 2-3, A: 3+
5. **Без ловушек** — не проверяем знание edge cases языка, проверяем понимание

### Концепты по доменам:

**Python**: переменные, типы, условия, циклы, списки, словари, функции, строки, list comprehension, классы  
**JavaScript**: переменные, типы, условия, циклы, массивы, объекты, функции, строки, DOM, callbacks  
**Frontend**: HTML-структура, CSS-селекторы, flexbox, grid, формы, анимации, адаптивность, семантика  
**Scratch**: движение, события, циклы, условия, переменные, клоны, ввод, списки, костюмы, звуки

## Story Guidelines (Экзаменационные)

- **Короткий** — строго 1 предложение
- **Лаконичный** — без развёрнутого нарратива
- **RPG-контекст** — минимальный, но присутствует

**✅ Хорошо:** "Гильдия проверяет навык работы с массивами."  
**✅ Хорошо:** "Финальное испытание: обработка данных инвентаря."  
**❌ Плохо:** "Великий маг Зефирус просит тебя помочь..." (слишком длинно)

```
Сгенерируй [N] экзаменационных заданий для домена [DOMAIN] tier [TIER].

Требования:
- Следуй JSON-схеме из EXAM_TASK_GENERATION_SPEC.md
- ID: exam_[domain_prefix]_[номер]_[концепт]
- Story: строго 1 предложение, лаконичный RPG-контекст
- Description: чёткое техническое задание на русском
- time_limit_minutes: [D=8, C=12, B=18, A=25]
- Проверяет навык, не обучает
- Без спойлеров к другим заданиям
- Каждое задание проверяет: [СПИСОК КОНЦЕПТОВ]
- Test cases: минимум 2 обычных + 1 hidden
- Initial code: с clear placeholder

Концепты tier [TIER]:
- D: 1 концепт (базовый)
- C: 2 концепта (комбинация)
- B: 2-3 концепта (продвинутый)
- A: 3+ концептов (экспертный)

Output: JSON массив, без пояснений.
```
