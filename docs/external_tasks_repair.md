## Что исправлено

В новых наборах проверяются допустимые входные данные: например, битовый массив состоит из 0 и 1 и заканчивается нулём, а размер части в Chunk Array положителен. Counter II проверяется через вызовы методов, включая независимость двух экземпляров. У операций удаления элементов проверяется изменение исходного списка, а не только возвращённое число.

Для задач с несколькими ответами проверяются свойства результата: длина и палиндромность, условия перестановки, корректность кода Грея, допустимость плана осушения и другие требования. Порядок элементов игнорируется только там, где это разрешено. Для дробных ответов учитывается численный допуск.

Примеры, подтверждённые по оригинальному решению, сами по себе не являются полным набором скрытых тестов. Это отдельный статус в отчёте.

## Источники и воспроизведение

Использованы [данные LeetCode](https://leetcode.com/problems/), [публичный API Codewars](https://dev.codewars.com/) и [исходный архив Codewars](https://github.com/AKleriX/codewars-tasks). Когда ссылка на конкретную ката не подтверждена, указан существующий файл условия в исходном архиве, а не угаданный адрес.

Подробный статус каждой задачи — в [external_tasks_audit.json](external_tasks_audit.json). `russian_statement_reviewed` относится к полному тексту условия, `test_status` — к проверкам. Идентификаторы, XP и прогресс пользователей сохранены.

```bash
venv/bin/python scripts/repair_external_tasks.py --fetch --workers 2
venv/bin/python scripts/repair_external_tasks.py --references --workers 4
venv/bin/python scripts/repair_external_tasks.py --codewars-sources --workers 4
venv/bin/python scripts/repair_external_tasks.py --apply --workers 4
venv/bin/python task_store.py --build
```

Загрузки кэшируются в `/tmp/pandora-external-repair` (можно указать `--cache`). При HTTP 429 загрузчик останавливается; повторный запуск использует сохранённые ответы. Оригинальные решения запускаются только в ограниченном раннере и не включаются в публичные данные задач.
